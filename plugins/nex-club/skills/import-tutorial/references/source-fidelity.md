# 格式保真与教程字段

用于把原始网页、Markdown、文字或文档映射为当前 Nex Club 教程，不改变原作者的内容范围。

## 来源和格式证据

先保留可对照的原始资料及来源定位：网页的原文链接与作者，文档的文件名和章节/页码，粘贴文本的用户说明。正文来源链接放入 `details.source_url`；没有公开原文时设为 `null`，文件名等补充信息放入 `details.notes`，不捏造网址。

富文本转 Markdown 时保留以下对应关系：

| 原始结构 | 转写与检查 |
| --- | --- |
| 标题 | 保留相对层级，使用 Markdown 标题；不要把字号大或视觉粗体全部改成标题。目录从实际标题生成，无需人为重编章节。 |
| 段落、换行 | 段落间保留空行，段内换行保留真实换行；不要把整个文档合成一个段落，也不要把每一行任意拆成段落。 |
| 加粗、斜体 | 从原始 Markdown、HTML `strong`/`b`、富文本样式或文档文字运行区间确认范围，再转为 `**…**` / `*…*`。普通文字维持普通字重，不按主观重点增删强调。 |
| 列表、引用 | 保留有序/无序类型、嵌套关系与引用边界；不要把列表压成一段文字。 |
| 代码 | 使用行内反引号或围栏代码块，保留语言、缩进、空行及原有字符；围栏长度须避免与代码内容冲突。不运行教程中的示例命令。 |
| 图片、链接 | 保留图片数量、顺序、说明文字、替代文字及原地址；相对 URL 依据真实来源解析。正文图片仍留在正文中，不只保留封面。 |
| 表格 | 使用 GFM 表格并转义单元格内的竖线；检查每行列数、表头和内容。合并单元格等无法等价表达的结构须说明并保留可访问的原始资料，不静默展平关系。 |

当前前端使用 `react-markdown` 与 `remark-gfm`，没有开启任意 HTML 渲染。不要把原网页 HTML 直接塞入正文来保留样式，也不要把脚本、事件属性、`javascript:` 链接或文档宏带入可执行环境。

曾有完整教程只转出纯文本，渲染器虽支持 `<strong>`，文章却没有任何强调节点。为防止复发，按原文对应区间核对渲染后的强调文本与数量，不能只检查全文文字相等或统一增加 CSS 字重。原文无强调或用户只提供纯文本时，不凭空补粗体。

中文标点贴近 `**` 时可能影响 Markdown 分隔符解析。例如 `点**「打开」**。` 需要验证实际渲染；可将相邻的“点”写成 `&#28857;**「打开」**。`，但解码后的文字必须相同。不要添加可见空格、移动强调范围或启用不受限 HTML 来掩盖问题。

## 图片可用性与预览

`cover_urls` 只接受 HTTPS 地址或已有的 `/covers/…` 路径。`body_markdown` 图片也必须能在目标站点读取；文件 ID、`file://`、本机路径、临时签名链接不能当作永久图片地址。没有现成资产上传工具时说明依赖，不虚构 `upload_image` 或自行改生产服务器。

选择原文合适的封面，`cover_urls[0]` 用于详情头图；不为了填满框架裁掉图片中的文字。预览时查看封面与正文图片是否完整、是否加载，桌面和窄屏下是否保持比例。若站点现有显示样式导致裁切，报告页面问题，不通过删图改变原文。

## 当前教程字段

创建草稿的 `body` 使用以下字段；示例只是字段形状，不是可直接执行的真实文章。工具参数、编辑与发布细节以 [字段与操作](../../manage-content/references/commands.md) 为准。

```json
{
  "kind": "tutorial",
  "slug": "ai-reading-notes",
  "title": "AI 辅助整理阅读笔记",
  "summary": "根据提供的材料整理笔记，并逐项核对引用。",
  "body_markdown": "## 整理步骤\n\n保留**原文强调**与段落。\n\n1. 记录来源\n2. 核对引用",
  "aliases": [],
  "cover_urls": [],
  "primary_category_id": null,
  "tag_ids": [],
  "quality_score": 50,
  "recommendation_reason": null,
  "details": {
    "level": "unknown",
    "minutes": 0,
    "steps": ["记录来源", "核对引用"],
    "author": "",
    "source_url": null,
    "notes": "根据用户提供的文字整理；作者及用时未提供。"
  },
  "change_reason": "按用户要求录入教程草稿"
}
```

- `title`、`summary` 不能为空。`body_markdown` 或 `details.steps` 至少有一个非空；全文导入应有完整正文。
- `slug` 为稳定的小写标识；新建前查重，编辑已有资源时不借机重命名。
- `details.level` 只支持 `unknown`、`beginner`、`advanced`，`minutes` 是非负整数，`steps` 是字符串数组。不要写入不存在的难度值或嵌套步骤对象。
- `quality_score` 为 0..100 的编辑评分；新建未评估时可沿用现有草稿示例的中性起点 50，明确它不是来源评分。更新时保留已有值，除非用户要求调整。
- `primary_category_id` 与 `tag_ids` 来自 `list_tags` 的有效 UUID；没有匹配项可分别为 `null` 和 `[]`。作者、时长、来源等未知信息不编造。
- JSON 中的 `\n` 应在解析后成为实际换行；不要二次转义成正文中可见的反斜杠 n。UTF-8 编码后的整个 `prepare_action.body` 上限为 64000 字节，超过时说明限制，不静默截断或把部分正文覆盖为全文。

## 保存前后核对

对照原始资料检查正文顺序与文字（仅忽略明确的格式编码差异）、标题层级、段落、强调范围、列表、表格、代码和图片。代码必须逐字一致；富文本强调核对范围，而不是只统计数量。浏览器预览需确认正文/加粗区分、长代码和表格滚动、图片与窄屏阅读。

有视觉工具时检查真实预览；没有时明确“语义结构已核对，视觉预览待检查”，不把 Markdown 解析成功称为视觉验收。`get_resource` 读回后的草稿正文也应与提交内容一致（服务端会修剪首尾空白）。

排查 schema 时，本仓库对应实现位于 `server/internal/httpapi/admin/mcp_tools.go`、`mcp_actions.go`、`resources.go` 以及 `server/internal/catalog/details.go`、`payload.go`。插件独立安装时以实际发现的 MCP schema 和返回结果为准。
